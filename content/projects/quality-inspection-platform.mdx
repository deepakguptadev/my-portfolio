## Overview

A production-floor quality inspection platform used by factory workers on iPads. It digitizes shoe inspection: workers identify a product by QR code or barcode, run quality checks, tag the defect area and defect type on an interactive vector image of the shoe, and submit the result for validation and approval or rejection.

## Context

The app runs in a factory, where speed, touch interaction, responsive layouts and intermittent connectivity all matter. The client is a React and Redux progressive web app; the backend is a set of Spring Boot microservices.

## My role

Senior Software Engineer on the frontend: designing UI wireframes and translating them into production code, enabling workers to scan QR codes and barcodes and tag defect areas on shoe vector images, managing offline support for production lines with intermittent to no Wi-Fi, keeping the app responsive on iPads and mobile devices, and writing unit tests.

## Engineering challenges

- **Factory-floor network instability.** Production lines had intermittent to no Wi-Fi coverage, yet inspections couldn't stop when the connection did.
- **Fast, repetitive inspection interactions.** Workers inspect product after product, so identifying a shoe and loading its vector image had to be quick.
- **Visual mapping of physical defects.** A defect on a real shoe had to be recorded as an area and a type on an interactive image.
- **Reliable client/server state.** Inspection data captured on the device had to stay consistent with the backend services.
- **Touch-first responsive UI.** The interface had to work by touch on iPads and stay responsive on mobile devices.
- **Production error handling.** Errors on the floor had to be handled without interrupting the inspection workflow.

## Decisions & tradeoffs

| Decision          | Why                                                | Trade-off                      |
| ----------------- | -------------------------------------------------- | ------------------------------ |
| PWA               | Tablet-friendly web delivery on the workers' iPads | Device and browser constraints |
| Redux             | Predictable state across the inspection workflow   | State complexity               |
| Microservices     | Backend domain separation                          | Distributed-system overhead    |
| Offline support   | Operational resilience when connectivity drops     | Synchronization complexity     |
| Automated testing | Regression protection                              | Test maintenance               |

## Outcome

Factory workers run real-time quality inspections on their iPads: scan a product, identify defects, and tag each defect's area and type on the shoe. Because the app is offline-first, inspections continue uninterrupted on lines with unstable connectivity, and defects are tracked accurately across production lines. QR-based product identification, inspection validation and approval/rejection steps streamlined factory-level shoe QA and improved operational efficiency for QA teams.
