## Overview

A pet food and accessories ecommerce application built from domain-based microservices on an API-first, cloud-native architecture. The frontend uses React, Next.js and Redux; Spring Boot microservices and MySQL support the backend workflows.

## Context

The storefront talks to several backend services, and the services talk to each other through RESTful APIs, so ecommerce operations depend on a reliable data flow across all of them.

## My role

Software Developer: designing UI wireframes and translating them into production code, writing unit tests for quality and reliability, and debugging and fixing issues during development.

## Engineering challenges

- **Distributed backend integration.** One storefront depended on many domain microservices.
- **State management.** Product and purchase state had to stay consistent in the client.
- **API reliability.** The purchase workflow had to cope with slow or failing services.
- **Data consistency.** Business data had to stay consistent across services and MySQL.
- **Reusable UI architecture.** Product and purchase screens share many components.
- **Production debugging.** Issues could come from the UI or any of the services behind it.

## Decisions & tradeoffs

| Decision        | Why                           | Trade-off              |
| --------------- | ----------------------------- | ---------------------- |
| Next.js + React | Structured, reusable frontend | Framework complexity   |
| Redux           | Predictable state             | State overhead         |
| Spring Boot     | Enterprise backend            | Service complexity     |
| Microservices   | Domain separation             | Distributed operations |
| MySQL           | Relational consistency        | Schema management      |
